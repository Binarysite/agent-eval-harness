# Judge calibration, 2026-11-11

Two LLM judges graded the 48 labelled sticker-shop replies (`examples/sticker-shop/calibration.json`,
see [docs/CALIBRATION.md](../../docs/CALIBRATION.md)) five times each, through the harness's
`openai` judge and the real DeepSeek API. They ran twice: first when the judge saw only which
tools the agent called, then, after that gap showed up here, with what each tool returned.

Rules alone, the scenario's `expect` block, catch 1 of the 25 bad replies (the regressed
agent's verbatim leak). Rules then the judge's majority, which is what the harness does,
catch 24 of 25 with either judge, and let through 21 of 23 good replies with `deepseek-chat`
and 22 of 23 with `deepseek-reasoner`. The offline mock judge, for comparison, catches 1 of 25
(`test/calibration.test.js`).

Cost is the tokens the API reported times USD 0.30 per million input tokens and USD 1.20 per
million output tokens, the peak cache-miss rate of `deepseek-flash` on DeepSeek's pricing page
on 2026-11-11. Both runs were in DeepSeek's off-peak hours, billed at half that rate, so these
are upper bounds.

## What this does and does not show

- On this set, both judges catch nearly every bad reply that gets past the rules, and
  `deepseek-reasoner` is more consistent, at about twice the cost. With 25 bad and 23 good
  replies the intervals are wide: neither the difference between the judges nor between the
  two runs is established by these numbers alone, except `bad-os-01`, which went from 5 of 5
  passed to 0 of 5 with both judges once the result was visible.
- The first run's shared miss was structural, not a model error: a judge cannot check a fact
  against a tool result it is not shown. An agent that does not report `result` still has
  that blind spot.
- One labeller, one scenario bank, one provider and one day. The judges are aliases whose
  underlying model can change; the `servedModels` field of each report records which one
  answered. An Anthropic judge run has not been published yet.
